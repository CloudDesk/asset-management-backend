# Auth Sessions Setup Guide

## 📋 Overview

This guide walks you through setting up the authentication session management system using **Prisma** instead of raw SQL. The system uses **node-cron** for scheduled cleanup (no pg_cron extension needed).

---

## 🚀 Quick Start

### Step 1: Install Required Package

```bash
npm install node-cron
npm install --save-dev @types/node-cron
```

### Step 2: Generate Prisma Migration

Run Prisma migration to create the `auth_sessions` table:

```bash
# Generate migration from schema changes
npx prisma migrate dev --name add_auth_sessions

# Or if you prefer to create migration manually
npx prisma migrate dev --create-only --name add_auth_sessions
```

This will:
- Create the `auth_sessions` table in your database
- Generate all indexes automatically
- Update Prisma Client with the new model

### Step 3: Update Prisma Client

```bash
npx prisma generate
```

### Step 4: Enable Session Cleanup Scheduler

Add the scheduler to your server initialization in `src/index.ts` or `src/server.ts`:

```typescript
import { scheduleSessionCleanup } from './utils/sessionCleanup.js';

// ... existing code ...

// Start session cleanup scheduler
scheduleSessionCleanup();

// ... rest of server startup ...
```

## 🔧 Usage Examples

### Creating a Session (During Login)

```typescript
import { authSessionService } from '../services/authsession.service.js';

// Inventory user login
const session = await authSessionService.createSession({
  userId: user.id,
  userType: 'inventory',
  refreshToken: 'your-generated-refresh-token',
  expiresInDays: 7,
  ipAddress: request.ip,
  userAgent: request.headers['user-agent'],
});

// E-commerce user login
const session = await authSessionService.createSession({
  userId: user.id,
  userType: 'ecommerce',
  refreshToken: 'your-generated-refresh-token',
  expiresInDays: 90,
  ipAddress: request.ip,
  userAgent: request.headers['user-agent'],
});
```

### Verifying Refresh Token

```typescript
const session = await authSessionService.verifyRefreshToken(
  refreshTokenFromRequest,
  'inventory' // or 'ecommerce'
);

if (!session) {
  // Token is invalid, expired, or revoked
  return reply.code(401).send({ message: 'Invalid refresh token' });
}

// Token is valid - proceed with issuing new access token
```

### Rotating Refresh Token

```typescript
const newSession = await authSessionService.rotateRefreshToken(
  oldRefreshToken,
  newRefreshToken,
  'inventory',
  7, // expires in 7 days
  request.ip,
  request.headers['user-agent']
);

if (!newSession) {
  return reply.code(401).send({ message: 'Invalid refresh token' });
}

// Return new tokens to client
```

### Logout (Revoke Session)

```typescript
// Single device logout
await authSessionService.revokeSession(sessionId);

// All devices logout
const revokedCount = await authSessionService.revokeAllUserSessions(
  userId,
  'inventory'
);
```

### Enforce Session Limits

```typescript
// Keep only 5 most recent sessions per user
await authSessionService.enforceSessionLimit(
  userId,
  'inventory',
  5 // max sessions
);
```

### Manual Cleanup

```typescript
import { runCleanupNow } from '../utils/sessionCleanup.js';

// Trigger cleanup manually (e.g., via admin endpoint)
const result = await runCleanupNow();
console.log(`Cleaned up ${result.deletedCount} sessions`);
```

## 🔄 Integration with Existing Auth Routes

### Update `/v1/auth/signin`

```typescript
import { authSessionService } from '../services/authsession.service.js';
import { generateAccessToken, generateRefreshToken } from '../utils/jwt.js';

// After successful authentication
const accessToken = generateAccessToken(user);
const refreshToken = generateRefreshToken(user);

// Create session
await authSessionService.createSession({
  userId: user.id,
  userType: 'inventory',
  refreshToken, // Will be hashed automatically
  expiresInDays: 7,
  ipAddress: request.ip,
  userAgent: request.headers['user-agent'],
});

// Optionally: Enforce session limit
await authSessionService.enforceSessionLimit(user.id, 'inventory', 5);

return {
  token: accessToken,
  refreshToken,
  expiresIn: 900, // 15 minutes
};
```

### Update `/v1/auth/refresh`

```typescript
const { refreshToken } = request.body;

// Verify old token
const session = await authSessionService.verifyRefreshToken(
  refreshToken,
  'inventory'
);

if (!session) {
  return reply.code(401).send({ message: 'Invalid or expired refresh token' });
}

// Generate new tokens
const newAccessToken = generateAccessToken({ id: session.userId });
const newRefreshToken = generateRefreshToken({ id: session.userId });

// Rotate refresh token (delete old, create new)
const newSession = await authSessionService.rotateRefreshToken(
  refreshToken,
  newRefreshToken,
  'inventory',
  7,
  request.ip,
  request.headers['user-agent']
);

return {
  token: newAccessToken,
  refreshToken: newRefreshToken,
  expiresIn: 900,
};
```

### Update `/v1/auth/signout`

```typescript
// Revoke all user sessions (logout from all devices)
await authSessionService.revokeAllUserSessions(
  request.user.id,
  'inventory'
);

return { message: 'Signed out successfully' };
```

## 🪄 pg_cron Alternative Explanation

### What is pg_cron?

pg_cron is a PostgreSQL extension that runs scheduled tasks **inside the database**. It requires:
- Installing the extension in PostgreSQL
- Database administrator privileges
- Extension enabled in the database

### Why We Don't Need It

We use **node-cron** instead, which:
- ✅ Runs in your Node.js application (no database extension needed)
- ✅ Easy to install: `npm install node-cron`
- ✅ No admin privileges required
- ✅ Portable across different PostgreSQL setups
- ✅ Can be started/stopped with your application

### How It Works

The `sessionCleanup.ts` file uses node-cron to schedule cleanup tasks:

```typescript
// Runs every day at 2:00 AM
cron.schedule('0 2 * * *', async () => {
  await authSessionService.cleanupExpiredSessions();
});
```

**Cron Format**: `minute hour day month weekday`
- `0 2 * * *` = Every day at 2:00 AM
- `0 */6 * * *` = Every 6 hours
- `*/30 * * * *` = Every 30 minutes

## 📊 Database Queries

### Check Sessions

```sql
-- All active sessions
SELECT id, "userId", "userType", "createdAt", "expiresAt", "isRevoked"
FROM auth_sessions
WHERE "isRevoked" = false AND "expiresAt" > NOW();

-- Sessions per user
SELECT "userId", "userType", COUNT(*) as session_count
FROM auth_sessions
WHERE "isRevoked" = false
GROUP BY "userId", "userType";

-- Expired sessions
SELECT COUNT(*) FROM auth_sessions WHERE "expiresAt" < NOW();

-- Revoked sessions
SELECT COUNT(*) FROM auth_sessions WHERE "isRevoked" = true;
```

## 🔒 Security Best Practices

1. **Never log refresh tokens** - They are sensitive credentials
2. **Always hash refresh tokens** - Done automatically by the service
3. **Enforce session limits** - Prevent session bloat
4. **Run cleanup regularly** - Use the scheduler
5. **Track IP and User Agent** - For security auditing
6. **Use HTTPS only** - In production

## ❓ Troubleshooting

### Migration Fails

```bash
# Reset and try again
npx prisma migrate reset
npx prisma migrate dev --name add_auth_sessions
```

### Scheduler Not Running

Make sure you called `scheduleSessionCleanup()` in your server startup:

```typescript
import { scheduleSessionCleanup } from './utils/sessionCleanup.js';
scheduleSessionCleanup();
```

### UUID Not Working

Make sure your PostgreSQL version supports UUID:
```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
-- OR for PostgreSQL 13+
CREATE EXTENSION IF NOT EXISTS "pgcrypto";
```

Prisma will use `gen_random_uuid()` which is built-in for PostgreSQL 13+.
